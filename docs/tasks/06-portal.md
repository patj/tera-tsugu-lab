## タスク

### 認証（スタッフの認証とは別にする）
- [ ] 招待コードの発行（個人ごと。推測できない値、有効期限つき）
- [ ] 招待コードでの登録: コードとメールアドレスを入力すると、`portal_accounts` ができる。コードは使用済みにする
- [ ] マジックリンクでのログイン: メールアドレスを入力すると、15 分有効で 1 回だけ使えるリンクを作る。**ハッカソン中は開発用の画面にリンクを表示する**（メールは送らない）。トークンはハッシュにして保存する
- [ ] ログインの状態を 30 日間保つ
- [ ] `/portal` 以下をログイン必須にする（登録とログインの画面を除く）
- [ ] テスト: 期限切れのリンク、使用済みのリンク、使用済みの招待コードを拒否する

### 権限（ドメイン層で判定する）
- [ ] 窓口かどうかは、世帯の `contact_person_id` で判定する（窓口が交代すると、新しい窓口に権限が移る。家族に与えた権限は残る）
- [ ] 家族の権限 `can_view_household`（家系図と法要の予定を見る）、`can_apply_memorial`（代理で法要を申し込む）。初期値はどちらもオフ
- [ ] 他の家の情報は見られない
- [ ] 上の判定のテスト

### 画面（`/portal`。スマートフォン向け、大きめの文字）
- [ ] ホーム: 立場に合わせて、できることを並べる
- [ ] 家系図（故人と、生きている家族。窓口、または `can_view_household` の家族） 【薄くできる: 一覧表示にする】
- [ ] 家の法要の予定（確定した法要と、今後の年忌の目安）
- [ ] 法要の申し込みフォーム（窓口、または `can_apply_memorial` の家族）: 故人（複数を選べば複数霊位供養。ポータルでは「複数の故人をあわせて供養する」と表示する）、施主（家族から選ぶか名前を入力。初期値は申し込んだ本人）、回忌（自動で提案。手で直せる）、第 1〜第 3 希望、場所、人数、お斎、連絡事項
- [ ] 法要の申し込みの状況（受付済み / 確定 / お断りと理由）
- [ ] 家族の権限の設定（窓口だけ） 【薄くできる: 固定にする】
- [ ] 行事の一覧と申し込み（05 のフォームを `source = portal` で回答する。`person_list` は家族を選ぶだけで入る）。自分の申し込みの確認
- [ ] 施設の空き状況（◯×）

### 管理画面（`/admin/portal`）
- [ ] 招待コードの発行と一覧（印刷できる形。QR コードはあれば）
- [ ] ポータルのアカウントの一覧（誰が登録したか、最後のログイン）
- [ ] 家族の権限の代行設定: 窓口の意向を確かめたうえでスタッフが設定する。監査ログと対応記録に残す

### シード（`src/db/seed/portal.ts`）
- [ ] 田中家の窓口（場面 5）と家族（権限 `can_view_household` をオン）のアカウント
- [ ] 山田さんのアカウント（場面 3）
- [ ] 未使用の招待コードを数件（登録の流れを見せる場合に使う）

## 決めること

- 家系図の描き方（自作の簡単な木、またはライブラリ）
