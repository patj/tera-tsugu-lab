# 07 台本の通し確認

> 段階 3。各機能の「完了の条件」の場面がそろったら行う。各場面は、機能ができた時点で個別に確かめてよい。
> 仕様: spec.md §10、§11

## 担当する範囲
- `src/db/seed/` のデモ用の調整（各機能のシードの担当者に依頼してもよい）
- `README.md`（起動とデモの手順）
- `docs/demo-checklist.md`（撮影の手順と確認表。作る場合）

## 依存先
- 00〜06 のすべて

## タスク

### デモのデータ
- [ ] シードの日付を、撮影日（11 月）から見て自然になるようにそろえる（「来月」= 12 月、山田家の七回忌の「3 月」= 2027 年 3 月）
- [ ] 台本と突き合わせて、各機能のシードを直す（依頼として各タスクファイルに書く）
  - 場面 0: 山田家の故人の候補が複数出る。七回忌の年が合う。3/15 が祥月命日より前。複数霊位供養の提案が出る。3 月中旬の候補に、空いていない時間が混ざる
  - 場面 1: 12 月に年忌を迎える家が、回忌ごとに数件ずつ出る
  - 場面 2: 田中家に三回忌を迎える故人がいる
  - 場面 3: 山田家に、`person_list` で選べる家族が複数いる
  - 場面 4: 12/6 午前の本堂と 12/13 午後の東席が空いている。法要と重ならない
  - 場面 5: 田中家の窓口と家族のアカウントがあり、家族は閲覧を許可されている。場面 0 の山田家と同じ法要が重ならない
- [ ] `npm run db:reset` で、いつでも撮影の前の状態に戻せることを確かめる

### 通しの確認
- [ ] 場面 0（法要の受付）を Claude Desktop で通す
- [ ] 場面 1（来月、年忌を迎えるお家）
- [ ] 場面 2（対応記録）
- [ ] 場面 3（ほうろく灸のフォーム。檀家の回答はポータル経由。間に合わなければ個別リンク）
- [ ] 場面 4（施設の申請と承認。申請はスマートフォンで）
- [ ] 場面 5（檀家ポータル。短く）
- [ ] 全場面を、`db:reset` から続けて通す
- [ ] 他人の私的な予定の内容が、どの画面と MCP の応答にも出ていないことを確かめる
- [ ] スマートフォンの画面（ポータル、公開フォーム、施設の申請と空き状況、自分の予定）を実機で確かめる

### 手順書
- [ ] `README.md` に、起動（docker compose、`.env`、`db:reset`、`dev`）と Claude Desktop の設定を書く
- [ ] 撮影の手順（画面の切り替えの順番、使うアカウント、Claude Desktop に話しかける文）をまとめる
