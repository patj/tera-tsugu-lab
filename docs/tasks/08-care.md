### シードとテスト
- [ ] シード: 共有している相談者（記録とアラートあり）と、共有していない相談者。本体の関数を通して作る（暗号文は本物）
- [ ] テスト: 暗号化（往復、改ざん、付け替え）、危機検知、同意（共有 → 撤回で見えなくなる、記録とアラートの両方）、MCP の拒否、監査ログ、DB に平文が残らないこと、`tools:check`

## 決めたこと
- プラグインはデータを読み書きしない。本体が復号した記録を props で渡す（spec.md §7）
- 共有し直すと、そのツールの過去の記録も見える。アラートは共有している間に保存した記録にだけ作る（あとから共有しても、過去の危機のアラートは作らない。記録の一覧には危機の印が出る）
- `text` と `textarea` は必ず危機検知の対象。`choice` は `crisis: true` のものだけ
- 匿名の ID の cookie（`tera_care`）はパスを `/care` にする（ほかの画面には送らない）
- 監査ログには、記録の本文を入れない（相談者の ID の先頭、ツールの ID、件数だけ）。監査ログの操作者の名前も、ニックネームではなく `care:相談者 <ID の先頭 8 文字>` にする
- 管理画面では、スタッフ全員が共有された記録を見られる（ハッカソン版。本番での限定は spec.md §8 の未決事項）
