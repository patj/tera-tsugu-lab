## 提供するインターフェース
**最初に作ってコミットする**（04 が使う）。

- `listOfficiants(templeId, conn?)` → `is_officiant` のスタッフ（`Staff[]`。表示順）
- `getStaffBusyIntervals(staffIds, { from, to }, conn?)` → スタッフごとの「埋まっている時間」（`Record<staffId, Interval[]>`。指定した全員のキーを持ち、重なりはまとめる）。私的な予定も含める（内容は返さない）。確定の前の確かめ直しでは `conn` に `tx` を渡す
- `createSharedEvent(actor, tx, { category, title, body, start, end, assigneeStaffIds, memorialServiceId? })` → 業務の予定を作り、ID を返す。04 が法要を確定するときに、同じトランザクションの中で呼ぶ。操作者がスタッフでない（シード）ときは、最初の担当者が作った人になる
- `cancelEventsByMemorialService(actor, tx, memorialServiceId)` → 法要の取り消しに合わせて、ひもづく予定を取り消す（取り消した件数を返す）
- `getCalendar(actor, { from, to, staffIds? })` → 表示用の予定。**閲覧者が本人でない私的な予定は、時間と「予定あり」だけにする**

## タスク

### ドメイン層
- [x] 予定の作成、更新、取り消し。私的な予定は本人だけが作れる・直せる。業務の予定は誰でも作れ、担当者を複数割り当てられる（ログインしない人の分も入れられる）
- [x] 私的な予定の内容の保護を**ドメイン層で**行う（`actor` が本人のときだけ内容を返す。MCP では `MCP_ACTOR` が本人）
- [x] 上のインターフェースとテスト
  - 他人の私的な予定は内容が返らない（Web、MCP の両方の `actor` で確かめる）
  - 私的な予定も「埋まっている時間」に入る
  - 業務の予定は、割り当てた全員の「埋まっている時間」に入る
- [x] 繰り返しの予定は作らない（§3.2）

## 決めること
- 日表示と週表示の時間の範囲（例: 6:00〜21:00）
  - 【決定】6:00〜21:00（案のとおり）。朝のお勤めから夜の会合までが入り、1 画面で見渡せるため。範囲の外にかかる予定（除夜の鐘など）は、日表示の「範囲外」の行に出す。MCP の `check_staff_availability` の 1 日の範囲の初期値も同じ（引数で変えられる）。定数は `src/domain/calendar/types.ts` の `DAY_START_HOUR` / `DAY_END_HOUR`
- カレンダーの部品を自作するか、ライブラリを使うか
  - 【決定】自作する（Server Components と Tailwind だけ）。依存を増やすとほかの worktree とのマージで衝突しやすく、日・週・月・リストの 4 種類は単純な表と絶対配置で作れるため。予定の編集だけを Client Component にした
- 【決定】週表示と月表示は月曜始まりにする。土日に行事が多いので、土日が週の終わりに並ぶほうが見やすいため
- 【決定】カテゴリの「私用」は私的な予定だけで使う（業務の予定と MCP の `create_staff_event` では選べない）。MCP の `create_staff_event` では「法要」も選べない（法要の予定は `book_memorial_service` が法要とひもづけて作るため。04 ができる前に、Claude が法要を単なる予定として登録しないように）。私的な予定は、ほかのカテゴリ（外出など）も選べる。私的な予定のカテゴリも内容の一部として、他人には返さない
- 【決定】予定の種類（私的 / 業務）は、作ったあとで変えられない。変えたいときは取り消して作り直す（私的な予定を業務に変えて、内容がうっかり全員に見えることを防ぐため）
- 【決定】法要にひもづく予定（`memorial_service_id` がある）は、カレンダーからは直せず、取り消せない。法要の画面（04）から変更・取り消しする（法要と予定の時間がずれないように）
- 【決定】他人の私的な予定は、ドメイン層の読み取りの入口（`selectEvents`）で、SQL の時点でタイトル・内容・カテゴリ・法要の ID を読まず、ID も返さない（`kind: "busy"` の形）。1 件の読み取り（`getEvent`）と書き換えでは、存在を明かさないように「見つかりません」にする。スタッフでない操作者（シードなど）にも内容を返さない。ポータルの操作者からはカレンダーを読めない
- 【決定】アルバイト（ログインしない人）は私的な予定を持たない。spec.md §3.2 の「私的な予定を入れるには本人のアカウントが必要」に従い、シードでもアルバイトの私的な予定は入れない（タスクの「アルバイトの私的な予定も含める」からは外れる）。私的な予定の例は奥様、寺務員、法要の担当者の 3 人に入れた
- 【決定】`createSharedEvent` を、スタッフでない操作者（04 のシードの `bookMemorialService` など）が呼んだときは、最初の担当者を作った人（`owner_staff_id`）にする
- 【決定】`listOfficiants` と `getStaffBusyIntervals` は `actor` を取らない（内容を返さないため）。`listOfficiants` はお寺の ID を受け取る。両方とも最後の引数に `conn`（`tx`）を渡せる
- 【決定】MCP のツールでは、スタッフを名前（空白は無視）、ふりがな、役職（住職など）で指定する（`resolveStaff`）。`check_staff_availability` でスタッフを省略すると、法要の担当者を対象にする。`create_staff_event` のプレビューで、担当者に重なる予定があれば注意を出す（内容は出さない。重なっても登録はできる）
- 【決定】管理画面の予定の操作は監査ログに残さない（spec.md §8 の監査ログの対象は MCP の呼び出しなどで、MCP の呼び出しは仕組みが記録する）
