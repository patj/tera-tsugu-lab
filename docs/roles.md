# 利用者ごとにできること

> 仕様書（[spec.md](spec.md)）の内容を、利用者の立場ごとに整理した資料。食い違ったときは spec.md を正とする。
> 記号: ◯ できる / △ 条件付きでできる（注を参照） / − できない / ？ 未決

## 利用者の立場

| 立場 | どんな人か | 入口 |
|---|---|---|
| **スタッフ** | 住職、副住職、執事長、奥様（寺庭婦人）、寺務員、アルバイトなど | 管理画面、MCP（Claude Desktop） |
| **檀家・施主** | 世帯の代表（`households.head_person_id` に設定されている人） | 檀家ポータル（招待コードで登録し、以降はメールのマジックリンクでログイン） |
| **檀家・家族** | 世帯に属する、施主以外の人 | 檀家ポータル |
| **檀家でない人** | 前撮りやお茶会の申込者、行事への一般参加者など | 公開ページ（ログインなし） |
| **相談者** | メンタルケアのツールを使う人。上のどの立場の人でもなりうる | ケアのポータル（匿名） |

※ 「相談者」は他の立場と重なりうる、横断的な立場。ケアのポータルは、ほかの立場のアカウントとは**ひもづけずに**匿名で使う（本人が希望した場合だけ、お寺と共有する）

## 未決事項（？の箇所）

- 檀家が自分で連絡先を直せるか（スタッフの確認を挟むか）
- 檀家が施設の利用（例: お茶会）をポータルから申請できるか
- 檀家でない人に、施設の空きの状況を公開するか
- 業務の権限はスタッフ全員同じ（ハッカソン版）。本番では、アルバイトが台帳やケアのデータを見られないようにするなど、ロールを分けることを再検討する
