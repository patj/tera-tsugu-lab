# 利用者ごとにできること

> 仕様書（[spec.md](spec.md)）の内容を、利用者の立場ごとに整理した資料。食い違ったときは spec.md を正とする。
> ※ お寺のアプリ（住職が Claude Code で作る小さな機能）は、基本機能のあとに組み込む（spec.md §7）。デモの台本には入れていない。
> ※ 【ハッカソン後】と付いた機能は、設計だけ決めてあり、ハッカソン版では実装しない。
> 記号: ◯ できる / △ 条件付きでできる（注を参照） / − できない / ？ 未決

## 利用者の立場

| 立場 | どんな人か | 入口 |
|---|---|---|
| **スタッフ** | 住職、副住職、執事長、奥様（寺庭婦人）、寺務員、アルバイトなど | 管理画面、MCP（Claude Desktop） |
| **檀家・窓口** | 家を代表してお寺とやりとりする人（`households.contact_person_id`。初期値は世帯主） | 檀家ポータル（招待コードで登録し、以降はメールのマジックリンクでログイン） |
| **檀家・家族** | 世帯に属する、窓口以外の人 | 檀家ポータル |
| **檀家でない人** | 前撮りやお茶会の申込者、行事への一般参加者など | 公開ページ（ログインなし） |
| **アプリの利用者** | お寺のアプリ（日記、占いなど）を使う人。上のどの立場の人でもなりうる | お寺のアプリ（`/apps`。匿名） |

※ 「窓口」は、台帳上の世帯主とも、法要ごとの施主とも別の概念（世帯主が窓口を兼ねることが多い）。法要の施主は、申し込みのたびに選ぶ
※ 「アプリの利用者」は他の立場と重なりうる、横断的な立場。お寺のアプリは、ほかの立場のアカウントとは**ひもづけずに**匿名で使う（本人が希望した場合だけ、お寺と共有する）

## 立場ごとの一覧

> 各立場の人が「何ができるか」を、その人の目線で並べたもの。機能ごとの詳細な比較は、後半の「機能ごとの一覧」を参照。

### スタッフ（住職、副住職、執事長、奥様、寺務員、アルバイトなど）
入口: 管理画面、MCP（Claude Desktop）

- **台帳・過去帳**: すべての世帯、個人、故人を見る・登録する・直す。離檀や転出は世帯の状態で表す（物理削除は【ハッカソン後】）。対応記録をつける
- **法要**
  - 年忌を迎える家を一覧する
  - 法要の申し込み（ポータルや電話で受けたもの）を確認する
  - 年忌を検証し（故人の取り違え、回忌と年の対応、命日より後の日でないか、複数霊位供養）、担当者と本堂の空きから候補を出し、日時を確定させる
  - 電話で受けた申し込みを、その場で確定する（申し込みも自動で記録される）
  - 申し込みを、理由を添えて断る
- **スタッフのカレンダー**
  - 業務の予定（法要、行事、外出、来客など）を見る・登録する・担当者を割り当てる（法要を確定すると、担当者の予定は自動で作られる）
  - 日（スタッフの横並び）、週、月、自分の予定（スマートフォン向け）の 4 つの表示で見る
  - 自分の私的な予定を登録する・内容を見る。他の人の私的な予定は「予定あり」と時間だけが見える
- **施設予約**: カレンダーで空きを見る。予約を登録する。申請を承認する・理由を添えて断る（申請中の予約と同じ時間に法要を入れるときは、先に申請を断る）
- **行事・アンケート**: フォームを作る・編集する（3 つの公開モード）。世帯ごとの個別リンクを発行する。集計を見る（回答の件数、祈願者などの人数）。回答と名簿を CSV で出力する（管理画面）
- **檀家ポータルの管理**: 招待コードを発行する。窓口を指定・変更する。【ハッカソン後】檀家からの連絡先の変更申請を承認する・差し戻す。窓口が未登録の場合などに、窓口の意向を確かめたうえで家族の権限を代わりに設定する（監査ログと対応記録に残る）
- **お寺のアプリ**
  - 利用者がお寺と共有したアプリの文書を見る（読むだけ。閲覧は監査ログに残る）
  - 住職は、Claude Code で新しいアプリを作る
- **MCP**: 上の業務（お寺のアプリの利用者のデータと、他人の私的な予定の内容を除く）を、自然言語で照会・登録・状態の変更（承認、お断りなど）をする（2 段階の確認を経る。削除と取り消しはできない）
- できないこと: 共有されていないアプリの文書を見る、他人の私的な予定の内容を見る、MCP でお寺のアプリの利用者のデータを扱う

### 檀家・窓口（お寺との窓口になる人）
入口: 檀家ポータル（招待コードで登録し、以降はメールのマジックリンクでログイン）

- **自分の家の情報**: 家系図（故人を含む）を見る。家の法要の予定（確定した法要と、今後の年忌の目安）を見る
- **法要**: 家を代表して法要を申し込む（故人の名前、施主、回忌、第 1〜第 3 希望、場所、人数、お斎の有無、連絡事項）。申し込みの状況（受付済み / 確定 / お断り）を見る
- **行事**: 行事（花まつり、ほうろく灸など）に申し込む（台帳でわかる項目は聞かれない簡易版。祈願者などの名簿は、家族を選ぶだけで台帳から入る）。自分の申し込みを確認する
- **家族の管理**: 家族ごとに「家の情報を見られる」「代わりに法要を申し込める」の権限を与える・外す
- **アプリの利用者として**: お寺のアプリを匿名で使う（ポータルのアカウントとはひもづかない）
- **施設**: 空き状況（◯×のみ）を見る
- 【ハッカソン後】家全体（世帯の住所、電話）と家族全員の連絡先の変更を申請する（スタッフの承認後に台帳へ反映される）
- 【ハッカソン後】ポータルから施設の利用を申請する（氏名や連絡先の入力は省ける）。ハッカソン版では公開ページから申請する
- できないこと: 他の家の情報を見る、法要の日時を自分で確定する

### 檀家・家族（窓口以外の家族）
入口: 檀家ポータル（招待コードで登録し、以降はメールのマジックリンクでログイン）

- **行事**: 行事に申し込む（簡易版）。自分の申し込みを確認する
- **窓口から許可された場合だけ**
  - 家系図と家の法要の予定を見る（`can_view_household`）
  - 窓口の代わりに法要を申し込む（`can_apply_memorial`。誰が申し込んだかが記録される）
- **アプリの利用者として**: お寺のアプリを匿名で使う
- **施設**: 空き状況（◯×のみ）を見る
- 【ハッカソン後】自分の分（メール、携帯番号）だけ、連絡先の変更を申請する
- 【ハッカソン後】ポータルから施設の利用を申請する。ハッカソン版では公開ページから申請する
- できないこと: 家族の権限を変える、許可なく家の情報を見る

### 檀家でない人（外部の利用者、行事への一般参加者）
入口: 公開ページ（ログインなし）

- **施設予約**: 施設の利用（前撮り、お茶会など）を申請する（申請した時点では仮押さえ。住職の承認で確定する）。申請番号で状況（申請中 / 確定 / お断りと理由）を確認する
- **行事**: 公開フォームから行事に申し込む（氏名や連絡先も入力する全項目版）
- **アプリの利用者として**: お寺のアプリを匿名で使う
- **施設の空き**: 公開ページで、空き状況（◯×のみ。予約の内容は見えない）を見る
- できないこと: 台帳、法要、カレンダーに関わること全般

### アプリの利用者（どの立場の人でもなりうる）
入口: お寺のアプリ（`/apps`。匿名。ニックネームだけで始められ、ID は端末に保存される）

- お寺のアプリ（住職が Claude Code で作る。日記、占いなど）を使う。アプリのデータ（文書）は本人だけが見られ、いつでも削除できる
- 共有に対応したアプリでは、アプリごとに「お寺と共有する / しない」を選ぶ。いつでもやめられる（やめるとすぐにお寺側から見えなくなる）
- 注意: 端末を変えたりデータを消したりすると、自分のデータには戻れない
- 利用者のデータは、MCP や AI からは一切参照されない

| できること | スタッフ | 窓口 | 家族 | 檀家でない人 |
|---|---|---|---|---|
| すべての世帯の台帳を見る・編集する | ◯ | − | − | − |
| 自分の家の家系図を見る（故人を含む） | ◯ | ◯ | △（窓口が許可した場合） | − |
| 自分の家の法要の予定（確定した予定と、今後の年忌の目安）を見る | ◯ | ◯ | △（窓口が許可した場合） | − |

| 家族にポータルの権限（閲覧、代理での申し込み）を与える | ◯（窓口の意向を確かめて代わりに設定。記録が残る） | ◯ | − | − |

## 未決事項

- **（ハッカソン後に決める）本番でのスタッフの権限の分け方**: ハッカソン版では、業務の権限はスタッフ全員同じ（私的な予定の内容だけは本人限定）。本番では、アルバイトが台帳を見られないようにする、削除や設定を管理者だけにする、などを検討する
