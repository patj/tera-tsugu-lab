# ケアのツールを Claude Code で作る手順書

> 相談に来る人のための「ケアのツール」を、お坊さん（または開発者）が Claude Code と一緒に作るための手順書。
> 仕様は [spec.md](spec.md) §7、Claude Code が守るルールは [tools/CLAUDE.md](../tools/CLAUDE.md)。

## 1. ケアのツールとは

相談に来る人が、スマートフォンで気持ちを書きとめ、あとから振り返るための小さな道具。
「こころのよりどころ」（`/care`）に並び、相談者は名前やメールアドレスなしで、ニックネームだけで使える。

ツールを作る人が考えるのは、**何を記録してもらうか（項目）と、どう見せるか（画面）だけ**。
次のことは本体（フレームワーク）が受け持つので、ツールの側で作る必要はない。

| 本体が受け持つこと | 内容 |
|---|---|
| 匿名の利用 | ニックネームだけで始められる。ID は端末の cookie にだけ保存する |
| 保存と暗号化 | 記録は AES-256-GCM で暗号化して保存する |
| 共有の同意 | 相談者がツールごとに「お寺と共有する / しない」を選ぶ。いつでもやめられ、やめるとすぐにお寺側から見えなくなる。変更の履歴を残す |
| 監査ログ | お寺側が記録を開いたこと、アラートを表示したこと、同意の変更を記録する |
| 危機検知 | 自由記述などに「消えたい」「死にたい」のような言葉があれば、本人に相談窓口を目立つように表示する。共有している人の場合は、管理画面にアラートを出す |
| 注意書き | すべての画面に「診断や治療は行いません」と相談窓口への案内を出す |
| AI からの保護 | ケアのデータは MCP（Claude Desktop）や AI からは一切読めない |

## 2. しくみ

```
tools/<tool-id>/          ← ツールを作る人が書く
  manifest.ts             名前、説明、アイコン、項目
  schema.ts               記録 1 件の型（zod）
  Entry.tsx               記録する画面
  History.tsx             振り返る画面（本人）
  AdminView.tsx           共有された記録を見る画面（お寺）
  README.md

npm run tools:gen         → src/care-sdk/registry.generated.ts / views.generated.ts（一覧。自動生成）

src/care-sdk/             ← ツールが import できる唯一の窓口（型と画面の部品）
src/domain/care/          ← 本体: 検証、危機検知、暗号化、同意、監査ログ
src/app/care/             ← 相談者の画面（/care）
src/app/admin/care/       ← お寺の管理画面（/admin/care）
```

- ツールは**データを読み書きしない**。保存のとき、本体は「manifest の項目でフォームの値を取り出す → manifest と schema で検証する → 危機検知 → 暗号化して保存」を行う。表示のときは、本体が復号した記録を画面に props で渡す
- だから、ツールの**うっかりした不具合**で、同意のない人の記録がお寺に見えることはない。ただし、ツールの画面はサーバーで動くコードなので、わざと規約を破るコードは防げない。`npm run tools:check` は、うっかりした違反（`fetch` や DB の import など）を見つけるためのもので、悪意のあるコードまでは見抜けない。**公開の前に、必ず人がツールのコードを読む**

## 3. 作り方（Claude Code）

### 3-1. 準備
```sh
docker compose up -d
cp .env.example .env      # はじめてのときだけ
npm install
npm run db:reset
```

### 3-2. Claude Code に頼む
このリポジトリで Claude Code を起動し、作りたいものを伝える。skill（`.claude/skills/new-care-tool/`）が呼ばれ、ひな形から作ってくれる。

頼み方の例:
- 「大切な人を亡くした方が、毎晩、故人に語りかけるように書けるツールを作りたい。その日の気持ちを 5 段階と、故人への言葉を自由に書けるように」
- 「写経のあとに、心に残った言葉と、今の気持ちを記録するツールを作って」
- 「眠りと食事と気持ちを毎日つけて、1 週間の移り変わりが見えるツールがほしい」

Claude Code は、足りないこと（項目の種類、振り返りで見せたいもの、名前とアイコン）をまとめて聞いてから作る。

### 3-3. 確かめる
```sh
npm run tools:check   # 規約違反が 0 件であること
npm run dev
```
※ `npm run dev` をすでに起動しているときは、ツールを足したあとに `npm run tools:gen` を流す（一覧の生成は `npm run dev` の起動のときにしか自動で流れない）

1. `http://localhost:3000/care` を開き、ニックネームで始める
2. ツールを選んで記録する → 「ふりかえる」で表示を確かめる
3. 自由記述に「消えたい」と書いて保存し、相談窓口が表示されることを確かめる
4. 「共有の設定」で「お寺と共有する」にする
5. もう一度、自由記述に「消えたい」と書いて保存する（アラートは、共有している間に書いた記録にだけ出る）
6. 管理画面（`http://localhost:3000/admin/care`。`jushoku@example.com` / `password`）で、共有した記録が見えること、共有中に書いた危機の記録がアラートになることを確かめる
7. `/care` に戻って共有をやめ、管理画面から見えなくなることを確かめる

### 3-4. 公開の前のチェックリスト
- [ ] `npm run tools:check`、`npm run typecheck`、`npm run lint` が通る
- [ ] 診断的な表現、点数で判定する表現がない（`tools:check` は代表的な言葉しか見ないので、文章を人の目でも読む）
- [ ] 自由記述の項目は危機検知の対象のまま（`crisis: false` がない）。つらい言葉を含む選択肢に `crisis: true` がある
- [ ] スマートフォンの画面で、文字が読みやすく、ボタンが押しやすい
- [ ] AdminView に、本人が共有した記録以外のこと（推測や評価）を出していない
- [ ] README に目的と項目が書いてある
- [ ] 人がツールのコードを読み、データの持ち出しや外部への送信をしていないことを確かめた（`tools:check` は悪意のある書き方までは見抜けない）
- [ ] できれば、住職や相談の経験がある人に、言葉づかいを見てもらう

## 4. 項目の型

| type | 入力 | 値 | 危機検知 |
|---|---|---|---|
| `text` | 1 行の文字 | 文字列 | 必ず対象 |
| `textarea` | 自由記述 | 文字列 | 必ず対象 |
| `scale` | 段階（1〜5 など）のボタン | 数 | 対象外 |
| `choice` | 選択肢から 1 つ | 選択肢の `value` | `crisis: true` のときだけ対象 |

詳しい設定と、`@/care-sdk` の部品は [tools/CLAUDE.md](../tools/CLAUDE.md) を参照。

## 5. `npm run tools:check` が見ること

- 必要なファイル（manifest、schema、Entry、History、AdminView、README）がそろっている
- manifest の `id` がディレクトリの名前と同じ。項目の `id` が重複していない。`schema` のキーと項目がそろっている
- import が `@/care-sdk`、`react`、`zod`、自分のディレクトリの中だけ
- `fetch` などの外部への送信、外部の URL、`process.env`、`localStorage` や cookie、`eval`、`"use server"`、`dangerouslySetInnerHTML` を使っていない
- 診断的な言葉（「診断」「うつ病」「症状」「治療」など）を使っていない
- 自由記述を危機検知の対象から外していない
- ツールの一覧（`*.generated.ts`）が最新

## 6. 決まっていないこと（ハッカソン後）

- お坊さんが作ったツールの審査と公開の流れ（今はリポジトリに入れて `tools:check` を通せば公開される）
- 相談者が端末を変えたときの引き継ぎ、檀家の台帳とのひもづけ
- ケアの記録を見られるスタッフの限定（今はスタッフ全員が、共有された記録を見られる）
- 危機検知のキーワードの見直し（`src/domain/care/crisis.ts`）と、相談窓口の番号の定期的な確認（`src/care-sdk/resources.ts`）
